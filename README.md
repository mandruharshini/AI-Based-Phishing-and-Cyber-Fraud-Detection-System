# Sentinel — AI-Based Phishing and Cyber Fraud Detection System

A small full-stack app matching the architecture:

```
User → Web App → { URL | Message } → Feature Extraction → ML Model
                                                        → Safe / Suspicious / Fraud
                                                        → Risk Score + Reasons
```

- **Backend:** Flask + scikit-learn (`backend/`)
- **Frontend:** single-page vanilla HTML/CSS/JS UI (`frontend/index.html`), served by Flask
- **Models:** two RandomForest classifiers — one for URLs, one for text messages — each outputting `Safe / Suspicious / Fraud` plus class probabilities used to compute a 0–100 risk score
- **Explainability:** every prediction is paired with a rule-based "Evidence" list generated directly from the extracted features (long URL, IP-address host, urgency language, requests for OTP/PIN, etc.)

## Setup

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt

# Models are already trained and included in backend/models/.
# To retrain (e.g. after changing feature_extraction.py):
python train_model.py

python app.py
```

Then open **http://localhost:5000** — the Flask app serves the frontend and the API from the same origin, so there's no CORS setup needed.

## API

**POST `/api/analyze/url`**
```json
{ "url": "http://secure-paypal-login.verify-account.xyz/update" }
```

**POST `/api/analyze/message`**
```json
{ "message": "URGENT: Your account will be suspended. Verify your OTP now!" }
```

Both return:
```json
{
  "classification": "Fraud",
  "risk_score": 87.5,
  "confidence": 91.2,
  "class_probabilities": {"Safe": 3.1, "Suspicious": 5.7, "Fraud": 91.2},
  "reasons": ["Uses urgency/pressure language: urgent, verify now", "..."],
  "input_type": "message",
  "input": "...",
  "raw_features": { "...": "..." }
}
```

## About the training data (important)

This environment has no internet access, so the models were trained on a **synthetic dataset** generated by `train_model.py`: feature vectors are sampled from distributions that mirror realistic Safe / Suspicious / Fraud behavior (based on the same signals used in `feature_extraction.py`), with 6% label noise so the classifier learns genuine boundaries instead of memorizing rules. On held-out synthetic data both models reach ~96% accuracy — that reflects fit to the synthetic distribution, not real-world performance.

**Before using this for anything real, retrain on labeled public datasets**, e.g.:
- URLs: [PhishTank](https://phishtank.org/), UCI "Phishing Websites" dataset, [OpenPhish](https://openphish.com/)
- Messages: UCI SMS Spam Collection, Kaggle "Fraudulent Email Corpus"

To retrain on real data: load your dataset, run each row through `extract_url_features` / `extract_message_features` to get a feature vector, and feed those vectors into `train_and_save()` in `train_model.py` in place of `generate_url_dataset()` / `generate_message_dataset()`. The API and frontend don't need any changes.

## Extending it

- **Add more signals:** WHOIS domain age, SSL certificate issuer, redirect chains, sender-domain/display-name mismatch for emails — add them to `feature_extraction.py` and retrain.
- **Swap the model:** `train_model.py` isolates data generation from training, so RandomForest can be swapped for XGBoost/LightGBM/a neural net without touching `app.py` or the frontend.
- **Persistence/history:** add a database (SQLite/Postgres) and a `/api/history` endpoint if you want to log past scans.
- **Auth/rate limiting:** add before deploying publicly, since this exposes an open POST endpoint.
